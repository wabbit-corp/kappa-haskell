```text
succ, max, and + should be ordinary resolved prelude operations.

But universe checking must recognize only the canonical compiler-owned TypeLevel instances of those operations,
not arbitrary user functions or user instances with the same names.
```

Otherwise the kernel starts calling library code to decide whether `Type u : Type v`, which is the formal-systems version of asking a raccoon to notarize a will.

The current spec still has `succ` and `max` directly in the solver-level expression grammar, plus derived `u + n` spellings. It also already has compiler-owned `Eq TypeLevel` and `Ord TypeLevel` via `__compareTypeLevel`, and the prelude already treats `+` as an overloaded prelude operation through numeric traits.

````text

```text
levelExpr ::=
    levelVariable
  | levelMetavariable
````

```kappa
1
2
n
ω

u + v
max u v

Type1
Typeω
```

```text
max u v    means the standard `max` operation at `TypeLevel`

Type0      means Type 0
Type1      means Type 1
Typeω      means Type ω
```

The universe solver recognizes resolved semantic operations, not source spellings.


````
Kappa provides compiler-owned intrinsic operations for `TypeLevel`.

The implementation behaves as if the following intrinsic heads exist:

```kappa
intrinsic __typeLevelZero :
    TypeLevel

intrinsic __typeLevelOmega :
    TypeLevel

intrinsic __typeLevelSucc :
    TypeLevel -> TypeLevel

intrinsic __typeLevelAdd :
    TypeLevel -> TypeLevel -> TypeLevel

intrinsic __typeLevelMax :
    TypeLevel -> TypeLevel -> TypeLevel
````

These intrinsic heads are solver-owned. They are reducible by the universe solver for solver-level expressions admitted
by §11.1.1. For open level variables, comparison may remain neutral unless level assumptions in scope force a result.

The standard prelude MUST expose these operations through ordinary standard typeclasses and ordinary standard functions.

The compiler-owned prelude evidence for `TypeLevel` includes at least:

```kappa

Ord TypeLevel

Zero TypeLevel
One TypeLevel
FromInteger TypeLevel

Successor TypeLevel
Add TypeLevel
Max TypeLevel
```

Source `instance` declarations for these `TypeLevel` instances are rejected.

```kappa

succ = __typeLevelSucc

add = __typeLevelAdd

max = __typeLevelMax

compare = __compareTypeLevel
```

The standard source spelling:

```kappa
ω
```

denotes:

```kappa
__typeLevelOmega
```

```kappa
u + v
```

uses the ordinary overloaded `+` operator resolved through `Add TypeLevel`.

The standard source spelling:

```kappa
succ u
```

uses the ordinary overloaded `succ` operation resolved through `Successor TypeLevel`.

The standard source spelling:

```kappa
max u v
```

uses the ordinary overloaded `max` operation resolved through `Max TypeLevel`.

The standard comparison operators:

```kappa
i == j
i <  j
i <= j
i >  j
i >= j
```

use the ordinary `Eq TypeLevel` and `Ord TypeLevel` instances.

The universe solver recognizes a source expression as a solver-level expression only when the resolved operations are
these compiler-owned standard `TypeLevel` operations, or transparent aliases reducing to them.

A source expression using an ordinary user function, user instance, shadowed operator, or nonstandard overload is not
recognized as a solver-level expression merely because it renders as `succ`, `+`, `max`, `<`, or `<=`.

Comparison expressions:

```kappa
i < j
i <= j
```

have type:

```kappa
Bool
```

When such Boolean expressions occur in erased proof-binder positions, the Boolean-to-type coercion of §11.4.2 applies:

```kappa
(@0 p : i < j)
```

means:

```kappa
(@0 p : (i < j) = True)
```

and:

```kappa
(@0 p : i <= j)
```

means:

```kappa
(@0 p : (i <= j) = True)
```

The universe checker recognizes erased proof binders of these forms as local level assumptions when the comparison
operators resolve to the compiler-owned `Ord TypeLevel` instance:

```text
@0 p : i <  j   introduces  succ i ≤ j
@0 p : i <= j   introduces  i ≤ j
```

The same recognition applies to explicit equality proofs:

```kappa
(@0 p : (i < j) = True)
(@0 p : (i <= j) = True)
```

and to transparent aliases reducing to those forms.

Compatibility aliases:

Portable Kappa keeps the following transparent aliases for compatibility and diagnostic rendering:

```kappa
type LevelLe (lo : TypeLevel) (hi : TypeLevel) : Type =
    (lo <= hi) = True

type LevelLt (lo : TypeLevel) (hi : TypeLevel) : Type =
    (lo < hi) = True
```

These aliases are not primitive traits.

A source program may write:

```kappa
(@0 p : LevelLt i κ)
```

but this is exactly equivalent to:

```kappa
(@0 p : i < κ)
```

and the Boolean comparison form is the canonical spelling.

Evidence for level-comparison propositions is proof evidence. It is runtime-erased.

The universe solver may synthesize proof evidence for a level-comparison proposition only when the comparison is valid
under the current local level assumptions. It MUST NOT synthesize evidence for self-containment comparisons such as:

```kappa
succ i <= i
i < i
ω + 1 <= ω
```

A level-comparison proof binder introduces an assumption only in its lexical scope. The assumption does not become a
global universe constraint and does not escape its binder scope.

````
```kappa
````

````
```text
````

with compiler-owned `TypeLevel` instances and no user-instance shenanigans. That is the difference between “uniform language design” and “the universe checker now depends on Bob’s local `max` function,” which is how a civilization begs for ruin.
